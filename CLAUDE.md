# Campfire Actions — project context for Claude

Purpose: S.T.A.L.K.E.R. 2 (UE5.5) mod that lets the player eat, drink, open the PDA, and inspect artifacts while seated at a campfire. Sibling of `stalker2-immersive-dialogue`; since its v2.0.0 (2026-09-14) that repo is a pure Zone Kit pak, and its `BUILD.md`, `zonekit/README.md` and `zonekit/tools/` are the template for every step here.

Current state: **planning, nothing built. Pak-only by design; no UE4SS layer.** Read `PLAN.md` first.

## Key facts (verified against ZoneKit on 2026-09-12)
- Campfire sit = `PlayerContextualAction` actor + `PC.contextual_action` bool + input context `IMC_PlayerCA` at priority Exclusive.
- `InputMappingContextPrototypes.cfg:294-298` (under `G:\Epic Games\STALKER2ZoneKit\Stalker2\Content\GameLite\GameData\`) is the IMC entry. Never ship a cfg override; add mappings to the `IMC_PlayerCA` asset instead.
- `PC` class members: `G:\Epic Games\STALKER2ZoneKit\bp_api_dump2.txt` from line 5141. Gate candidates: `can_use_inventory` (5153), `contextual_action` (5163), `is_interaction_in_progress` (5218), `is_using_pda` (5224), `is_inspecting_artifact` (5217), `start_use_pda` (5360), `start_use_backpack` (5359), `consume_planned_item` (5162).
- Player-state enums are only in `bp_api_dump.txt` (`PlayerTriggerState` at 5084).

## Rules
- **ZoneKit first.** Grep the dumps and cfgs, and ask Noah to open assets in the Mod Editor, before any blind build/test cycle. Most `/Script/Stalker2` classes are native; look for assets that USE them, not the classes.
- **Assets this mod may override:** `IMC_PlayerCA`, the sit-actor Blueprint (`BP_PlayerContextualAction`), `BP_Stalker2Bonfire` (sleep stretch only). **Never** `BP_Stalker2Character`, `AnimBP_Player`, `AnimBP_player_bh`, or any `.cfg`: the first two are ImmersiveDialogue's, and per asset the last-mounted pak wins outright, so a user with both mods would lose one.
- **Mount order.** Every test and release pak is `zzz_CampfireActions_20_P.{pak,ucas,utoc}` in `Stalker2\Content\Paks\~mods\`. Kit paks mount at 3, `_P` mods at 103, `_10_P` at 1103; a lower name loses silently (that cost ImmersiveDialogue an evening).
- **Canary.** Every test build keeps an extra key on `IA_PlayerCAExit` so "override not loaded" and "action vetoed" are distinguishable in-game. Remove it for release.
- **Change discipline.** One change per cook (5-6 min), tested by Noah before the next. Checkpoint working states as tagged commits with the cooked pak in `zonekit/builds/`.
- **UE4SS is dev-only.** A read-only probe (ImmersiveDialogue's `ImmDlgProbeCpp` or Lua shape, listed before `UObjectCacheMod` in `mods.txt`) may run on the dev box. Nothing UE4SS ships.

## Pipeline (copied from ImmersiveDialogue v2; details in its BUILD.md)
- Plugin lives at `<kit>\Stalker2\Mods\CampfireActions\`; mirror changed `.uasset`s back into `zonekit/CampfireActions/` in this repo after every save. The mod folder is the editor's source of truth.
- Override an asset: Content Browser → right-click → *Checkout selected content to mod plugin folder*. Keep only files meant to ship in `Content/`; delete any `Autogenerated_*_ActorReplacementData.uasset` unless the plan says otherwise.
- `IMC_PlayerCA` override is generated headlessly: `Stalker2ModEditor-Win64-Shipping-Cmd.exe "<kit>\Stalker2\Stalker2.uproject" -run=pythonscript -script=<script> -unattended -nosplash -stdout -NoShaderCompile` (about 4.5 min). Use the moved-objects technique from ImmersiveDialogue `BUILD.md` §5.2 (`rename(outer=…)` from a duplicated `IMC_Exploration`); the committed `make_imc_override.py` predates that fix.
- Cook: `RunUAT.bat GSCCookMod "-Project=<kit>\Stalker2\Stalker2.uproject" "-PluginPath=<kit>\Stalker2\Mods\CampfireActions\CampfireActions.uplugin" "-PackageClassifierOutputDir=<kit>\Stalker2\SavedMods\PackageClassifier\CampfireActions" "-UnrealExe=<kit>\Stalker2\Binaries\Win64\Stalker2ModEditor-Win64-Shipping-Cmd.exe" -TargetPlatform=Win64 -nocompile -nocompileuat`. `OverridePackages.txt` / `NewPackages.txt` in the classifier dir list what to cook.
- Install waits for `Stalker2-Win64-Shipping.exe` to exit, then copies the three `*OverrideContent.*` files renamed to `zzz_CampfireActions_20_P.*`.
- Editor traps carried over: save before compile; wait ~10 s after a save before cooking; Property Access nodes only inside AnimGraphs (not relevant unless an anim asset is ever touched, which it should not be).
