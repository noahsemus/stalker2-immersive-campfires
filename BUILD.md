# Building ImmersiveCampfires (Zone Kit pak)

This document is for anyone who wants to rebuild, modify or extend the mod. It
covers the toolchain, what the mod changes and exactly how, how to cook and
install it, and the traps we hit. **Nothing is built yet**; sections 2 and 5
are filled in as each layer of [PLAN.md](PLAN.md) lands.

Paths assume the kit at `G:\Epic Games\STALKER2ZoneKit` and the game at
`C:\Program Files (x86)\Steam\steamapps\common\S.T.A.L.K.E.R. 2 Heart of Chornobyl`;
adjust in the scripts if yours differ.

## 1. Prerequisites

- **S.T.A.L.K.E.R. 2 Zone Kit** (GSC's Unreal 5.5 mod editor), from the Epic
  Games Store. First launch compiles shaders and can take a long time.
- ~600 GB free where the kit lives.
- Git, and this repository cloned somewhere short-pathed.

No Python installation is needed; the kit ships its own
(`Engine\Binaries\ThirdParty\Python3\Win64\python.exe`).

## 4. Build the mod from the committed source

1. Copy `zonekit\ImmersiveCampfires\` to `<kit>\Stalker2\Mods\ImmersiveCampfires\`.
2. Copy `zonekit\tools\classifier\ImmersiveCampfires\*.txt` to
   `<kit>\Stalker2\SavedMods\PackageClassifier\ImmersiveCampfires\`.
3. `powershell -File zonekit\tools\cook_and_install.ps1`. This runs the same
   UAT command as the editor's *Package Mod* button:
   ```
   <kit>\Engine\Build\BatchFiles\RunUAT.bat GSCCookMod
       "-Project=<kit>\Stalker2\Stalker2.uproject"
       "-PluginPath=<kit>\Stalker2\Mods\ImmersiveCampfires\ImmersiveCampfires.uplugin"
       "-PackageClassifierOutputDir=<kit>\Stalker2\SavedMods\PackageClassifier\ImmersiveCampfires"
       "-UnrealExe=<kit>\Stalker2\Binaries\Win64\Stalker2ModEditor-Win64-Shipping-Cmd.exe"
       -TargetPlatform=Win64 -nocompile -nocompileuat
   ```
   5-6 minutes. Output under
   `<kit>\Stalker2\SavedMods\Staged\ImmersiveCampfires\Windows\{OverrideContent,NewContent}\...\Content\Paks\Windows\`.
4. The install step copies the OverrideContent files to
   `<game>\Stalker2\Content\Paks\~mods\zzz_ImmersiveCampfires_PakTest\` renamed
   `zzz_ImmersiveCampfires_30_P.{pak,ucas,utoc}` (the NewContent files, if any,
   keep the kit's name). Release zips use `_20_P`. Mount priority is
   3 + 100 × (N+1) for a `_N_P` suffix; kit-named paks mount at 3 and lose to
   any other mod overriding the same asset.

The *Package Mod* button is still needed once if the mod has a
`ModWorldSubsystem`: only it generates `Autogenerated_<n>_WorldSubsystemData`.

## 6. Editor and pipeline traps

Inherited from ImmersiveDialogue (its BUILD.md §6 and zonekit/README.md):

- The cook picks up **everything** in the mod's `Content` folder regardless of
  the classifier lists; keep only files meant to ship there. Delete any
  `Autogenerated_*_ActorReplacementData.uasset` the editor drops unless an actor
  override needs it.
- A package listed in both classifier lists is cooked into neither.
- An override Blueprint's reference to a mod-only asset is silently nulled in
  the cook; NewContent Blueprints may reference NewContent assets.
- The editor redirects `/Game` picks of an overridden asset to the mod path;
  load the game-path object by path string when it matters (rebinds apply
  only to it).
- **Save before Compile** on big edits; wait ~10 s after a save before cooking.
- After any asset rename, Compile (bytecode is stale until then) and re-check pins.
- `duplicate_asset` returns None in the live editor for `/Game` sources; run
  such scripts headless with the editor closed.
- The **mod folder is the source of truth** for the editor; mirror changed
  `.uasset`s back into `zonekit/ImmersiveCampfires/`.
- Blueprint "Float" variables are doubles.

## 7. Diagnostics

`Print String` is stripped in Shipping. Use the canary mapping (PLAN.md Layer
1) to tell "override not loaded" from "action vetoed", visible side effects in
Blueprints, and on the dev box only a UE4SS probe (copy ImmersiveDialogue's
`ImmDlgProbeCpp` or Lua probe; list it before `UObjectCacheMod` in `mods.txt`).
Graphs can be read back as text: Ctrl+A / Ctrl+C in the editor, then read the
clipboard.
