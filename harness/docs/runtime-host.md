# Running Blueprint logic without overriding anything

The preferred home for mod logic: a **`ModWorldSubsystem` Blueprint in NewContent** that spawns a mod actor. It
overrides no game asset, so it cannot conflict with other mods, and NewContent Blueprints keep their references to
other NewContent assets (`pipeline.md` § cook rules). Proven by Immersive HUD (`BP_ModWorldImp` → `BP_ModActorImp`),
ZST (`BP_ZoneWatchSubsystem.OnTick`), ImmersiveDialogue 2.1 (`Runtime/BP_ImmDlgSubsystem`) and ImmersiveCampfires
(`Runtime/BP_ImmCampSubsystem` → `BP_ImmCampActor`).

## Recipe
1. `/<Mod>/Runtime/BP_<Short>Subsystem`, parent `ModWorldSubsystem`, listed in NewPackages.txt.
2. Press **Package Mod** once in the editor: it generates `Autogenerated_<n>_WorldSubsystemData` (a soft class path
   to the subsystem) into the mod's Content and adds it to OverridePackages.txt. Without it the game never creates
   the subsystem. Mirror it into the repo.
3. `OnInitialized` → `SetTickEnabled(true)`: a ModWorldSubsystem does not tick until enabled.
4. `OnTick`: `Branch(IsValid(<Actor var>))` False → `SpawnActorFromClass(BP_<Short>Actor)` → set the variable. Keep
   ticking and re-spawn when invalid: a spawn-once-then-stop-ticking graph spawned too early and the actor was gone
   (Campfires build 1). One subsystem per world (`WorldMap_WP`); the actor lives in `PersistentLevel`.
5. The actor: CDO `AutoReceiveInput = Player0` (set from Python) or `EnableInput`, EnhancedInputAction events for
   its keys, per-tick logic with edge detection (do the work on state changes, not every frame).
6. Get the pawn with `Get Player Pawn` → `Cast To PC` (the native player class; `BP_Stalker2Character_C` at runtime).

## Rules of thumb
- Only the subsystem data asset (and any unavoidable overrides) goes in the override pak; everything else is
  NewContent.
- Never scan all objects per tick (`ForEachUObject` / `GetAllActorsOfClass` every frame stalls the game thread; a
  1.44 s stall once read to players as "no control"). Read from owners (pawn components, mesh linked instances,
  camera manager modifier list).
- A tick prerequisite (`AddTickPrerequisiteComponent`) makes the actor tick before e.g. the player mesh when order
  matters.
- Settings live in actor/subsystem variables with defaults, so the main mod needs nothing else; an optional MCM
  add-on writes them (`compatibility.md` § MCM).
